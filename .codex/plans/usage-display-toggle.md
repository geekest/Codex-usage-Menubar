# 用量显示模式切换

## 1. 任务目标

当前菜单栏和菜单详情固定显示“已使用”百分比。新增一个菜单按钮，让用户可以在“已使用”和“剩余”两种显示模式之间切换；切换后菜单栏标题与两条详情同步更新，例如已使用 21% 和 10% 时显示“5 小时剩余：79%”与“每周剩余：90%”。

## 2. 当前状态

- `UsageTextParser` 将网页中的已使用或剩余文案统一解析为“已使用”百分比。
- `UsageSnapshot` 保存 5 小时和每周的已使用百分比，并生成固定的菜单栏标题。
- `MenuBarController` 使用 AppKit `NSMenu` 展示固定的“已使用”文案。
- 现有测试覆盖解析逻辑。基线构建成功，但中文“剩余”解析用例已有一项失败：每周 80% 剩余被误解析为 75% 已使用。

## 3. 目标状态

- 菜单中提供单一切换按钮。
- 默认显示“已使用”；点击后显示“剩余”，再次点击恢复“已使用”。
- 菜单栏标题和菜单详情始终使用同一显示模式。
- 剩余百分比由规范化后的已使用百分比计算，空值保持 `—`。
- 切换不触发网络刷新，也不改变解析和存储语义。

## 9. 决策记录

### Decision：保持快照的已使用语义

选择：`UsageSnapshot` 继续只存储已使用百分比，在显示层计算剩余值。

原因：现有解析器已统一数据语义，可避免重复转换和网络逻辑变化。

备选方案：把显示模式放进 `UsageStore`，或让快照同时保存两种百分比。

影响：切换是纯 UI 行为，风险和改动范围更小。

### Decision：使用单一动态菜单项

选择：按钮根据当前模式显示“显示剩余”或“显示已使用”。

原因：符合单按钮切换需求，也沿用当前 AppKit 菜单结构。

备选方案：两个带勾选状态的菜单项，或自定义分段控件。

影响：交互简洁，不引入自定义视图。
