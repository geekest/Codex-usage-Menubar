# 修复菜单栏启动流程

## 目标

- 确保手动创建的 `NSApplication` 完成启动生命周期并初始化菜单栏。
- 确保中文 ChatGPT 页面能够进入用量文本读取流程。

## 执行计划

- [x] 修复应用启动流程，保证启动代理回调被触发。
- [x] 补齐页面就绪检查的中文标签。
- [x] 执行可用的静态检查和解析器行为验证。
- [x] 审查改动并记录 macOS 实机验证项。

## 已定位原因

- 当前入口直接调用 `app.run()`，但没有显式完成手动创建应用所需的启动阶段；菜单栏只在 `applicationDidFinishLaunching` 中创建，因此回调未触发时不会出现状态项。
- JavaScript 页面就绪检查只识别英文标签，中文页面会持续重试并最终超时，即使 Swift 解析器已经支持中文。

## 结果复盘

- 已在进入事件循环前调用 `finishLaunching()`，使 `applicationDidFinishLaunching` 能够创建并持有菜单栏控制器。
- 已让页面就绪检查同时识别中英文用量标签，避免中文页面等待超时。
- Swift 语法解析、解析器类型检查、中文真实文本行为检查及 `git diff --check` 均通过。
- 当前 Linux 环境缺少 `AppKit`，仍需在 macOS 上确认菜单栏实际显示和 WebKit 登录流程。
