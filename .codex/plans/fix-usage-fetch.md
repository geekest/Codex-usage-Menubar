# 修复菜单栏用量读取

## 1. 任务目标

修复用户在内嵌页面完成 ChatGPT 登录后，菜单栏仍显示“需要登录”且不显示用量的问题。完成后，登录后到达可读取的用量页面会自动更新菜单栏中的 5 小时和每周已用比例。

## 2. 当前状态

- `ChatGPTWebSession` 仅处理由 `loadUsagePage()` 创建的 `WKNavigation`。
- 初次加载被导向登录页时，当前实现会立即使请求失效并发布 `needsLogin`。
- 用户在同一 `WKWebView` 完成登录后的新导航不属于原始 `WKNavigation`，因此被忽略，页面虽显示用量，菜单状态却不更新。
- `UsageTextParser` 在中文“剩余”文本中可能将上一个窗口的百分比匹配给“每周”窗口；当前已有失败测试覆盖该问题。

## 3. 目标状态

- 登录中的非用量页只提示需要登录，不丢弃后续同一会话的成功导航。
- 登录完成后出现用量页时自动读取文本并更新状态。
- 解析器将每个窗口优先匹配标签之后的百分比，避免相邻窗口串值，同时保留百分比在标签之前的兼容性。

## 4. 范围边界

### 本次包括

- 修复 WebKit 导航状态与登录后读取流程。
- 为导航决策和中文用量文本添加回归测试。
- 运行 Xcode macOS 构建、Swift 测试和启动冒烟验证。

### 本次不包括

- 更改登录方式、存储登录凭据或访问用户账户数据。
- 改造菜单栏界面或增加新的网络依赖。

## 8. 新发现与意外情况

- 发现：Xcode 的 Swift Package Scheme 可选择 iOS 模拟器；在该目标下 `AppKit` 不可用。正确使用 `My Mac` 可完成构建。
- 影响：与本次用量读取无直接关系，但验证必须使用 macOS 目标。
- 处理方式：所有 Xcode 验证显式指定 macOS 运行目标。

## 9. 决策记录

### Decision：以页面可读性而非固定路径判断登录完成

选择：允许来自受信任 ChatGPT 域名的后续导航进入页面读取，只有真正显示登录页或达到读取超时才保持登录提示。

原因：用户交互触发的登录导航没有初始 `WKNavigation` 标识，固定路径会把成功登录后的页面错误忽略。

备选方案：登录成功后强制重新加载固定 URL。

影响：减少对站点重定向路径的耦合，保留现有受信任域名限制。

## 11. 风险与回滚

- 风险：ChatGPT 页面结构或文案变更可能导致读取超时。
- 缓解：保留中英文标签和受信任域名校验，并使用失败状态提示用户。
- 回滚：回退本分支的单次提交即可恢复原导航逻辑。

## 12. 最终结果与复盘

- 实际完成：受信任的 ChatGPT 用量页在登录后的新导航中也会进入读取流程；无关导航仍被忽略。百分比匹配优先使用标签之后的数值，缺失时才回退到标签之前的数值。
- 修改文件：`UsageStore.swift`、`UsageTextParser.swift`、`UsageTextParserTests.swift` 与本执行计划。
- 验证：新增导航回归测试和截图中文页面文本测试；`swift test` 通过 11 个测试；显式使用 macOS 目标的 Xcode 构建通过；应用短时启动无立即崩溃。
